## 🧠 What I Studied Today

### 1️⃣ What is Infrastructure as Code (IaC)?

Infrastructure as Code is the practice of managing infrastructure using code instead of manual processes.

Key takeaways:

* Infrastructure becomes **repeatable and predictable**
* Changes can be **version-controlled**
* Environments stay **consistent** across teams

This helped me understand why IaC is considered a foundation skill in modern cloud roles.

---

### 2️⃣ What is Terraform (Conceptually)?

Rather than focusing on commands, I focused on Terraform’s role:

* It is a **declarative** tool
* We define the *desired end state*
* Terraform figures out *how* to reach that state

This mental shift made Terraform feel less like a collection of commands and more like a **system that manages infrastructure lifecycle**.

---

### 3️⃣ Declarative vs Imperative Approach

This comparison brought a lot of clarity:

* **Imperative:** Step-by-step instructions (how to do it)
* **Declarative:** Final desired state (what it should look like)

Terraform follows the declarative approach, which explains:

* Why `plan` exists
* Why Terraform can detect changes
* Why state management is critical

---

### 4️⃣ Terraform Core Workflow (High-Level)

Instead of memorizing commands, I focused on understanding the flow:

1. Initialize the working directory
2. Review what changes Terraform *plans* to make
3. Apply changes to reach the desired state

Understanding this workflow conceptually helped me connect actions to outcomes.

---

### 5️⃣ Why Terraform State Matters

This was a key realization today.

Terraform needs a **source of truth** to:

* Track existing resources
* Compare desired vs actual state
* Safely update infrastructure

The state file is not just a file — it is the backbone of how Terraform operates.
